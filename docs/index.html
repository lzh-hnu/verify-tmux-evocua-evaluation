Verification Brief

This companion page treats evaluation as a trace-audit problem: can reviewers recover what EvoCUA saw, decided, and repaired?

The content varies from the adapter page by emphasizing reproducibility, sampling, and measurable failure categories.

Check Question

How can an EvoCUA evaluation protocol prove that tmux traces are comparable across repeated runs?

Trace Notes

  • Runs are grouped by task family and terminal profile.
  • Trace samples include successful, repaired, and abandoned attempts.
  • Measurements distinguish agent choice from terminal transport behavior.

Review Lens

  • Run-to-run comparability
  • Repair path visibility
  • Failure category separation

Verification Discussion

A useful evaluation page should make disagreement inspectable. The verification stance is therefore less about perfect scores and more about stable evidence.

Additional work can connect these static notes to dashboards that expose per-run pane history and recovery timing.
